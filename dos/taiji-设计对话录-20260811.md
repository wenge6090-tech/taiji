## 一、taiji 的定位：配合生成范式的推理时工程

### 核心命题

模型能力上限由预训练地形（权重）决定，且**无法后训练**。taiji 不改变模型，
而是**配合模型的生成范式**——把任务组织成模型训练过的任务形式（完形填空/接龙），
用系统结构（验证/回退/拆解/沉淀）补偿模型的结构性缺陷。

- **被提升的**：多步任务成功率、任务复杂度上限、跨任务有效知识
- **不被提升的**：单次 token 质量（地形决定）

这有正式名称：**inference-time compute scaling（推理时计算扩展）**——o1/R1、
verifier 路线、agentic 框架都在验证同一方向。

### 与生成式模型的一体两面

| Transformer | taiji |
|---|---|
| 权重矩阵（持久） | 归藏资产树（持久） |
| 前向传播（生成） | TPN 执行（Meta 编排 → Fitting 采样 → Causal 验证） |
| 反向传播（训练） | DMN 更新（trace 统计回传 → fork/merge/prune） |
| 损失函数 | 回报函数（四维：通过率/质量/token 成本/验证轮数） |

## 二、与 prime-agent 的对比（诚实评估）

**prime-agent 是 pi 的硬 fork**（官方文档原文 "began as a hard fork of pi-mono"），
底层 TUI/会话/压缩/skills 体系同源。taiji 与它是不同物种：prime 是产品，taiji 是认知内核研究。

| 维度 | prime-agent | taiji | 更自洽者 |
|---|---|---|---|
| 上下文满了 | 压缩（湿痕浓缩回注入） | 交接（干涸重来，只传产物） | taiji——压缩污染新采样 |
| 验证 | 无独立验证相位 | 阴相位一等公民（V33 起三权分立） | taiji |
| 学习 | /refine 手动、session-local | DMN trace 自动回传、跨任务（未激活） | taiji 方向更闭环 |
| 子任务失败 | 返回结果交 LLM 处理 | 结构化失败汇报 + rerun 再指导（V31） | taiji |
| 工程成熟度 | daemon/TUI/调度成熟 | 研究代码，213+ 测试 | prime |
| 持久 IPython | 有（代码即工具） | 无（5 L1 Skills） | prime |

**结论**：taiji 的独特价值在 prime 架构没有的东西——①独立验证相位 + 结构化失败路由
（可靠性）；②自动沉淀跨任务知识（进化性）。兑现前提 = DMN 激活 + V33 契约化落地。

## 三、DMN 应该记录什么（选择标准）

只记录**模型仍未覆盖且已验证**的知识，四条件缺一不可：

1. 模型覆盖度低（私有环境/时效/长尾/特定工作流）
2. 复用频次高
3. **已验证**（多次复现 + 验证通过——写入门槛防幻觉污染）
4. 稳定（易变知识带 env_tags）

分类（阴阳双轨）：

| 轨道 | 资产 | 记录内容 |
|---|---|---|
| 阳轨（生成） | prompts/ | 角色模板 |
| 阳轨（生成） | workflows/ | 特殊工作流 + 稳定涌现文本 + 脚本模板 |
| 阴轨（验证） | verifications/ | **收敛验证契约**（V33 升级为结构化 CheckSpec） |
| 硬约束 | truths/ | 环境事实 + 不可违反规则 |
| 统计层 | models/ | 预留（连山流型） |

**验证本身是需要知识的**——数学用 sympy、代码用编译器+测试、事实用搜索、特定工作流
有自己的验收判据。CausalAgent 的 verify 模板是通用的，但没有"这个领域怎么验证"的知识
——V33 的 ContractEngine 正是补这一块。

## 四、DMN = MCTS 认知树（V32 设计）

**TPN 是执行的马尔可夫链（MCMC），DMN 是蒙特卡洛探索 fork 树（MCTS）**：
每次 TPN 执行 = 一次 rollout，DMN 持久累积统计并驱动演化。

- **回报函数写死**（BCP §6.4）：`reward = 0.5·pass + 0.3·quality − 0.2·cost − 0.1·rounds`
  ——四维信号全部来自既有数据（trace usage / VerificationReport / verify_state），
  零新增持久化文件。回报函数 = DMN 的改进方向，系统价值判断，不由 LLM 自定。
- **UCB 选择**（§6.3）：`score = avg_reward + C·√(ln N_total / N_node)`；N=0 最大探索分；
  n < min_samples（3）只走探索分——探索-利用平衡。
- **MCTS 四算子**（§6.4）：backprop（γ=0.5 父链衰减）→ fork（复制+降权，内容修订走人工，
  DMN 不调 LLM）→ merge（相似变体合并）→ prune（N≥5 且低于组内最优 >2σ 淘汰）。
- **被动 + 主动学习双轨**：被动 = trace 回传（任务驱动）；主动 = 空闲窗口对高不确定性
  节点跑模板化探索任务（信息增益驱动，护栏：不递归/预算上限/窗口限量）。
- **归藏按模型分区**（§6.1）：不同模型预训练地形不同，资产不可跨模型混用——
  `.taiji/knowledge/{model_key}/`，model_stats.yaml（元权重表）在根。
- **元权重 = 模式决策 + 模型路由**（§8.8）：MetaContext 新增 model 字段，ModelRouter
  bandit 决策（成本感知：贵模型必须通过率显著更高才被选）——多小模型分治。

## 五、V33 缘起：概率系统不能验证概率系统

会话中讨论"验证器退化风险"（阴也是 LLM，可能把关不严）时，用户指出收敛验证的
符号化方向。随后 BCP 更新为 V33：

**归藏本体论重构**——归藏不是 RAG 知识库，而是「验证契约库 + 生成资产库」：

- verifications/ 从自由文本升级为**结构化验证契约**（`checks: Vec<CheckSpec>`）
- **ContractEngine** 在 CausalAgent LLM 调用之前执行 L0 机械验证 + L1 契约验证
- **机械检查失败直接短路，LLM 不可翻案**；LLM 只裁决 llm_judgement 类检查项（L2 兜底）
- 实证依据：MM-JudgeBias（ACL 2026：26 个 judge 验证完整性失败）、
  Reliability without Validity（arXiv 2606.19544：21 个裁判模型高可靠性低有效性）
- MVP 三步走（§8.23）：MVP-1 契约 schema + ContractEngine（纯 TPN 侧）→
  MVP-2 DMN 统计回传（检查项粒度）→ MVP-3 MCTS 契约演化

**V33 是 V32 的深化**：DMN 统计对象从「资产」精确到「检查项」，MCTS 四算子作用于
契约有效性空间。

## 六、关键教训（第一性原理审视三相循环）

一个简单的多 agent 编排（Meta → Fitting → Causal → route）的可靠性由**数据契约自洽**
保证。三条第一性原理：

1. **辅助数据失败不得瘫痪主流程**——归藏资产只是"锦上添花"的认知偏置，它的格式
   问题废掉了元相全部功能（V27 资产重写后元相静默失效，所有任务裸奔）。
2. **失败必须可见、必须可恢复**——`if let Ok(...)` 吞错、parse 失败静默降级、
   Agent 不挂 TraceHook = 三重隐藏。LLM 是概率性的：一次失败必须重试。
3. **数据契约必须有容错与测试**——手写/外部生成的资产文件必须与代码 serde 契约
   兼容；测试不能只覆盖"自己 save 自己 load"。

延伸：**软约束（模板教学）拦不住 LLM 的心理模型，注册面（工具/预算）才是兜底**——
编排节点"先理解再拆解"导致读爆，教学层加规则无效，最终用 60k 交接阈值（注册面）
强制"快拆"。
