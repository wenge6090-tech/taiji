# 实现计划

套用 `plan.md` 转化协议，基于当前蓝图（或直接给定目标 $@）生成结构化实现计划：

- **目标**（一句话）
- **模块清单**（`file` — 说明，精确到文件粒度）
- **接口签名**（关键函数/类型签名）
- **依赖顺序**（先 X 再 Y，附原因）
- **验收标准**（可测量条目：测试命令 / 编译检查 / 冒烟步骤）

补充行为说明：$@

要求：
- 引用 `Blueprint.md`（设计定论：哲学 + Mermaid 图）与 `AGENTS.md`（实现事实：环境 + 路径索引 + 规则）；接口签名经 AGENTS.md 路径索引定位到**代码文件**确认，不重复造规则。
- 计划中发现蓝图假设无法落地（拆分不合理、类型约束不满足、依赖循环），在这里就指出阻塞点与替代方案，不要拖到实现阶段。
- 产出后用户确认即进入实现阶段（按 APPEND_SYSTEM.md 的三阶段模式执行）。
