# taiji 项目工作流：三文件 + 三阶段

仅在本目录内启动 pi 时加载。其他目录的工作不受影响。

## 三文件（事实分层）

| 文件 | 本质 | 加载时机 |
|------|------|---------|
| `Blueprint.md` | 设计定论（设计哲学 + Mermaid 图） | 设计/架构/改契约时读 |
| `plan.md` | 转化协议（平时空） | 任务需计划时套用 |
| `AGENTS.md` | 实现事实（环境 + 路径索引 + 避坑规则，自动加载） | 每次会话实时加载 |

> **核心原则：代码是最精确的实现。** 接口签名、类型字段、数据结构以**代码为准**——文档不重复存实现细节，只做**路径索引**（AGENTS.md）+ **设计图/哲学**（Blueprint.md）。

数据流：`Blueprint(设计) --plan.md协议转化--> 具体计划 --执行--> 代码`；经验固化回流——**避坑 → AGENTS.md**、**设计定论 → Blueprint.md（需用户批准）**、**接口/类型变更直接改代码（不重复写文档）**。

## 阶段一：蓝图（仅用户要求时）
- 先 read `Blueprint.md` 确认既有**设计哲学 + Mermaid 架构图**，再动笔。
- 产出：总装图（模块边界、调用/依赖、数据流方向）+ 部件图（关键 struct/enum/trait 与字段），**全部用 Mermaid 语法**，每图带标题说明。
- 设计定论冲突时以 `Blueprint.md` 为准；实现层命名/类型以**代码**为准，不改蓝图。

## 阶段二：计划（仅用户要求时）
- 套用 `plan.md` 转化协议，把蓝图转化为结构化实现计划：目标（一句话）/ 模块清单（精确到文件粒度）/ 接口签名 / 依赖顺序（含原因）/ 验收标准（可测量）。
- 接口签名经 `AGENTS.md` 路径索引定位到**代码文件**确认，不重复造规则。
- 蓝图假设无法落地（模块拆分不合理、类型约束不满足、依赖循环无法打破）时，在此阶段就指出阻塞点与替代方案，不要拖到实现阶段。

## 阶段三：实现 + 自测（用户要求实现时）
- 按计划串行实现，每完成一个模块输出一行「模块摘要：改了哪些文件 + 关键决策」。
- 自动执行测试命令（见 AGENTS.md，本项目为 `cargo test`）；失败自动修复并重试，最多 3 次；仍失败则输出失败详情并停止，等待用户介入。
- 通过后按「固化回流」归档经验：边界条件/异常处理/易错点 → `AGENTS.md` 末尾（格式：`- 规则描述`）；设计级洞察 → `Blueprint.md` 定论（需用户批准）；接口/类型变更只改代码，文档更新路径索引即可。

语言风格：直接、简洁、工程化；先给结论/方案，再给必要说明。
