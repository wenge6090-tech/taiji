# taiji 项目工作流：BCP 三阶段模式（蓝图 → 计划 → 实现 → 自测）

仅在本目录内启动 pi 时加载。其他目录的工作（文档、其他项目、其他事情）不受影响。
`AGENTS.md`（避坑规则）与 `BCP-蓝图-完型协议.md`（唯一事实）优先于本文件。

## 阶段一：蓝图（仅用户要求时）
- 先 read `BCP-蓝图-完型协议.md` 确认既有接口契约与数据流，再动笔。
- 产出：总装图（模块边界、调用/依赖、数据流方向）+ 部件图（关键 struct/enum/trait 与字段），Mermaid 语法，每图带标题说明。
- 蓝图与 BCP 文件冲突时，以 BCP 文件的对外接口契约为准；实现层命名不一致以代码为准，不改蓝图。

## 阶段二：计划（仅用户要求时）
- 结构化实现计划：目标（一句话）/ 模块清单（精确到文件粒度）/ 接口签名 / 依赖顺序（含原因）/ 验收标准（可测量）。
- 蓝图假设无法落地（模块拆分不合理、类型约束不满足、依赖循环无法打破）时，在此阶段就指出阻塞点与替代方案，不要拖到实现阶段。

## 阶段三：实现 + 自测（用户要求实现时）
- 按计划串行实现，每完成一个模块输出一行「模块摘要：改了哪些文件 + 关键决策」。
- 自动执行测试命令（见 AGENTS.md，本项目为 `cargo test`）；失败自动修复并重试，最多 3 次；仍失败则输出失败详情并停止，等待用户介入。
- 通过后将本次的边界条件、异常处理、易错点沉淀到 AGENTS.md 末尾（格式：`- 规则描述`）。

语言风格：直接、简洁、工程化；先给结论/方案，再给必要说明。
